Board is split into layers, so other apps can embed and extend it. `@neta-art/cohub/board` is the model and now defines item types: `defineBoardItem` declares a type (namespaced extension types like `acme.order` with a props schema, or a built-in) and `createBoardRegistry` collects them for one editor, stage or export. New subpaths carry what used to live only in the Cohub web app: `board/editor` is a framework-free editor engine (`createBoardEditor`, state read through getters and `subscribe(channel, listener)`, so it plugs into `useSyncExternalStore`, Svelte or signals); `board/replica` keeps a local copy in step with the server (`createBoardReplica({ remote: space.board(id), storage })`); `board/stage` draws an editor with PixiJS and routes input to it (`mountBoardStage`), with DOM item views for content the canvas cannot host. Breaking: `board/headless` is now `board/export/node` (`createBoardHeadlessRenderer` → `createNodeBoardRenderer`, `createBoardHeadlessSketchHost` → `createNodeBoardSketchHost`, `BoardHeadless*` types → `BoardNode*`, `boardHeadlessMimeType` → `boardImageMimeType`); the player (`createBoardPlayer`, `nextLocalPlayback`, `playbackTimeAt`) is imported from `board/player` only; the global `registerShapeDefinition`, `registerBoardCardRenderer` and `shapeBounds`/`shapeHitTest`/`shapeCapabilities` are replaced by a registry (`registry.capabilities(item)` and friends) and `createBoardCardRendererResolver(renderers)`; `BoardClient` is constructed from `{ http, websocket, spaceId, boardId }` (use `space.board(id)` as before). Stored documents are unchanged.

Board 拆分为分层结构，方便其他应用嵌入和扩展。`@neta-art/cohub/board` 是模型层，现在负责定义 item 类型：`defineBoardItem` 声明一种类型（带 props schema 的命名空间扩展类型如 `acme.order`，或内置类型），`createBoardRegistry` 为一个编辑器、舞台或导出汇总这些类型。原本只存在于 Cohub web 应用中的能力移到新的子路径：`board/editor` 是与框架无关的编辑器引擎（`createBoardEditor`，通过 getter 和 `subscribe(channel, listener)` 读取状态，可直接接入 `useSyncExternalStore`、Svelte 或 signals）；`board/replica` 维护与服务端同步的本地副本（`createBoardReplica({ remote: space.board(id), storage })`）；`board/stage` 用 PixiJS 绘制编辑器并把输入交给它（`mountBoardStage`），画布无法承载的内容可用 DOM item view 呈现。破坏性变更：`board/headless` 改为 `board/export/node`（`createBoardHeadlessRenderer` → `createNodeBoardRenderer`，`createBoardHeadlessSketchHost` → `createNodeBoardSketchHost`，`BoardHeadless*` 类型 → `BoardNode*`，`boardHeadlessMimeType` → `boardImageMimeType`）；播放器（`createBoardPlayer`、`nextLocalPlayback`、`playbackTimeAt`）只从 `board/player` 导入；全局的 `registerShapeDefinition`、`registerBoardCardRenderer` 以及 `shapeBounds`/`shapeHitTest`/`shapeCapabilities` 由注册表（`registry.capabilities(item)` 等）和 `createBoardCardRendererResolver(renderers)` 取代；`BoardClient` 改为用 `{ http, websocket, spaceId, boardId }` 构造（照常使用 `space.board(id)` 即可）。已存储的文档不受影响。
